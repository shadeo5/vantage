Events & Opportunities

How time-bound events (a festival, a state fair, a carnival) live alongside evergreen spots — and how the system reconciles them into one ranked answer to "what should I shoot right now?"

01

The core tension

Spots and events are architecturally opposite. Model that difference up front or it gets painful later.

Spots (built)Events
LifespanEvergreen — always thereTime-bound — a window, then gone
Change rateSlow (curate once, cache)Fast (appear / expire daily)
SourceOSM + content pipelineExternal feeds + editorial
Eligible when?AlwaysOnly inside its window
The decision

Keep them separate at storage (different tables, different refresh cadence) and unified at ranking (one scorer, one list). Never jam events into the spots table.

02

The unifying abstraction: Opportunity

To the ranker and the UI, a spot and an event are both "a reason to shoot." Normalize both into one shape:

Opportunity {
  kind:       'spot' | 'event'
  name, lat, lon, category
  timeWindow: null              // spot — always eligible
            | { start, end }  // event — eligible only in-window
  photoValue                  // THE gate — is there a real photo here? (too low → dropped)
  magnitude                   // draw / attendance — amplifies, does NOT qualify
  content:    { why, look[], getting }   // the "why" IS the photoValue test
  source
}

A spot has timeWindow: null. An event carries its window and a magnitude. Now one scorer ranks them together — that's "understanding events against the rest of the data."

03

Sourcing — the hard part

No single API has everything (we already hit this: the World Cup wasn't in Ticketmaster). Layer the sources:

LayerCoversNote
Ticketmaster / SeatGeekConcerts, big sports, some festivalsFree-ish keys
ESPN (unofficial)Sports schedulesFree, complete — proven
PredictHQCommunity events, festivals, fairsPaid — but gives a predicted attendance/rank = your magnitude, solved
Editorial / tentpoleMarquee known-ahead (state fair, Dragon Con) & what APIs missHand-pinned
Honest flag

The long tail — state fairs, pop-up carnivals, street festivals — is exactly what ticketing APIs miss. It probably needs PredictHQ + editorial, not free APIs alone. This is the single hardest data problem in the product.

04

How an event competes with a spot

Two mechanics make events rank correctly in the shared scorer:

  • Time-gating (a filter). An event only enters the pool when now is inside its window (or the week ahead, for planning). Spots always qualify. So a state fair simply isn't in the running except during its run.
  • Urgency + magnitude boost. An evergreen spot is "always there." An event is "here now, gone next week" — and that scarcity is exactly what makes a great nudge. Events get a boost because they're transient.
Key idea

Events are where the app's timeliness comes from. A big event should out-rank an evergreen spot this weekend and vanish from the list the following Monday.

04·5

The photography lens — the gate

Everything is scored through a photography lens. Not every event earns a slot — some just aren't worth shooting, no matter the crowd.

Photo value ≠ attendance. PredictHQ tells you the draw; it says nothing about whether there's a photo in it. That's a separate call — and it's the one that matters.

Top marks — shoot it
  • Dragon Con parade — costumes, spectacle
  • Renaissance fair — color, characters, craft
  • Fair / carnival — neon, crowds, rides after dark
  • Lantern & light festivals, markets, cultural parades
Not worth it — drop
  • Corporate conference / trade show
  • Ticketed indoor lecture or talk
  • Photo-restricted, with a dead exterior

Two layers do the filtering:

  • Category priors — a cheap first pass. Auto-drop the inherently un-photographic (conferences, lectures, expos) before spending an LLM call.
  • Per-event assessment — the LLM judges within a category: a marquee costume parade vs. a sleepy craft fair.
The operational test

The LLM's ability to write a genuine, specific "why shoot this" is the score. If the best it can manage is "there'll be people there," the event is dropped. This is the "just knows where to shoot" instinct made concrete — the same pipeline that drafts what to look for doubles as the filter for whether to bother.

  • Photo value is the gate; magnitude only amplifies. A giant conference scores ~0 and drops out; a modest lantern festival scores high. Draw is a multiplier among the shootable, never a qualifier.
  • Where it sits: an enrichment step between ingestion and the feed — the scorer only ever sees photographically-viable opportunities.
  • It applies to spots too (the lens is universal) — but it bites hardest on events, since external feeds rank by attendance, not by whether there's a frame in it.
05

Co-location: the eclipse rule

When an event and a spot share a location, you don't show both. Whichever scores higher becomes the headline; the other folds in as context.

For the Dogwood Festival at Piedmont Park, nobody's going for the meadow that weekend — they're going to Dogwood, which happens to be at Piedmont. The event is the attraction; the spot demotes to venue.

Normally
Piedmont Park
Nature · golden hour · Midtown skyline
Piedmont is the attraction.
During Dogwood (Apr)
Dogwood Festival
at Piedmont Park · flower crowns, artist stalls
Event = attraction; Piedmont = venue. Reverts Monday.

This isn't a hardcoded "events beat spots" rule — it falls out of the same scorer, because a big event just outscores the spot-as-attraction. A tiny meetup at Piedmont would lose — the park still headlines and the event is a footnote. One rule handles both.

Inherit vs. override — the clean seam

When the event headlines and absorbs the spot as venue, it splits the spot's data in two:

Place-intrinsic → inherit from spotEvent-intrinsic → override with event
CoordinatesThe subject (festival, not meadow)
Getting there / parking / transitWhat to look for
Light geometry ("skyline west, golden ~8:15")Crowd / energy / timing
Photo history of the placeThe headline & the window

Logistics and light don't change just because there's a festival — those are facts about the place, so the event borrows them for free. Only the subject flips.

  • A location's role is contextual, not fixed. Piedmont is an attraction by default and a venue while Dogwood runs. Role is computed at ranking time from what's active there — don't type a place as permanently spot-or-host.
  • It's temporal. When the window closes, the eclipse lifts and the spot headlines on its own again.
  • Standalone events have nothing to inherit. A carnival in a parking lot isn't a known spot → it stands alone with its own coordinates + generated logistics. Spot-inheritance is a bonus when the geo-link exists, not a requirement.
06

Content for events

An event has no curated "what to look for." The content pipeline extends here — but keyed by category instead of a fixed place:

  • Fair → ferris wheel at blue hour, candid portraits at the food stalls, midway lights after dark
  • Carnival → motion blur on the rides, neon reflections, ticket-booth characters
  • Concert / festival → crowd energy, stage light spill, the queue before doors

Same LLM recipe as the spot pipeline (voice guide + structured output), different input: an event type, optionally fused with the venue spot's place-facts.

Update (2026-07-16) — first catalog is hand-curated, not category-generated. The initial editorial seed, content-pipeline/content/atlanta-events.json (12 marquee Atlanta events), was hand-curated per event — each carries its own why/look plus per-archetype kitAngles (wide/normal/tele/macro) — rather than generated from an event type. Reason: the marquee tentpoles are few, high-value, and specific enough that per-event editorial beats a category template; the category-keyed generation above stays the scale path once the long tail is ingested. Sourcing strategy that fed the curation: EVENT_DATA_SOURCES.md.

08

Open decisions

  • Is timeliness the point, or a feature? If "there's a fair tonight, go" is a huge part of the value, events are co-equal with spots and the time-boost is central. If events are occasional seasoning on an evergreen base, the ranker leans differently.
  • Pay for PredictHQ to get the fair/carnival long tail (and free magnitude scores), or start editorial-only and stay narrow?
  • How trustworthy is the LLM's photographic-value call? It's a taste judgment — validate it the way we validated the drafted content, and set the drop threshold (how weak a "why" gets an event cut).
  • Magnitude normalization — among the shootable events, how do you compare "state fair" to "gallery opening" without PredictHQ's attendance score? Editorial tiers?
  • Dedup strategy across overlapping sources (the same festival from Ticketmaster and PredictHQ).
  • Eclipse threshold — how much must an event outscore a spot before it takes the headline vs. sits as a footnote?
