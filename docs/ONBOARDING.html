01

What Vantage is

Vantage is a nudge-first street-photography scouting app. Once each evening it quietly buzzes a photographer — but only when tonight's light and their gear actually line up — and tells them where to shoot, why it's worth it, and how to shoot it. The opposite of a directory you have to go dig through: it comes to you, and only when it has something real to say.

Who it's really for: the dormant camera owner as much as the active street shooter — someone who owns good gear but hasn't picked it up in months. The North Star is blunt: "the best camera is the one you actually pick up." Vantage isn't serving existing intent (people already deciding where to go) — it's creating it, reaching out first with one reason to shoot today. The founder (Desha) is a street photographer himself, which shapes the taste; the strategic target is the person who needs a reason to start again.

Where it is today: a built Expo/React-Native app on a live Supabase backend that pushes a real notification to a real phone, nightly, on its own. Two cities are live in the database — Atlanta (16 spots) and Nashville (13) — plus a growing curated event catalog. The north-star loop — nudge → shoot → return → check-in — is closed end-to-end.

The one-sentence pitch

"Your phone tells you the light's good tonight, points you at the right spot for the camera in your bag, and shows you the shot to make when you get there."

02

The mental model

Four ideas explain most decisions in this codebase. Learn these and the rest reads easily.

1 · Nudge-first, not browse-first

The product's job is inspiration, not search. A "quiet night" honestly shows less (or nothing) rather than padding a list — the app would rather say nothing than nag. The home screen curates a single hero + a short, quality-gated set, never the whole pack.

2 · A pure "brain", a thin UI

All the real decision logic lives in vantage/lib/ as pure, testable functions — no React, no I/O. "Is tonight worth it? Which spot? Which lens? What to shoot?" are all answered there and unit-tested. The React components are a thin skin that renders what the brain returns. When you're reasoning about behaviour, read lib/; when you're reasoning about pixels, read components/.

3 · The "Opportunity" abstraction

A spot (evergreen — a place that's always there) and an event (time-bound — here now, gone next week) are architecturally opposite, but to the ranker and the UI they're both just "a reason to shoot." They're normalised into one shape and run through one scorer. Everything is judged through a photography lens: attendance/magnitude never qualifies an event — only whether there's a real photo in it does.

4 · Honesty is a feature, not a nicety

This is the project's strongest through-line, and it's enforced in code and copy:

  • Never fake data. No invented hours, no fabricated "0.8 mi away" distances when there's no GPS. If we don't know it, we don't say it.
  • Illustrations, not fake photos. Spot imagery is honestly-stylised AI art, never stock passed off as a real photo of a real place.
  • Gear is "ideal-for", never a limit. The app tells you what your kit is great at and how to make tonight work — it never tells you your gear "can't."
  • Inferred, not metered. Light and weather are computed from sun position + forecast, so the copy hedges accordingly ("looks like a fast-glass night", never a fake lux reading).

Architecture at a glance

Four moving parts. The app reads from Postgres; a nightly cloud job pushes the nudge; a content pipeline fills the database; and a pure brain decides everything in between.

The database is filled by a five-stage content pipeline (Node scripts) with a human gate before any money is spent:

1 · Curate
OSM/Overpass → genre-scored, diversity-capped candidates + a vet page
2 · Vet 👤
a human keeps/edits the shortlist → committed vetted/*.json
3 · Draft
Claude writes on-voice copy → committed content/*.json
4 · Image
GPT Image 1.5 → WebP <300KB → Storage bucket
5 · Serve
importer → seed.sql → Postgres; app & nudge read it
The both/and data model — worth internalising early

Git-committed per-city JSON is the source of truth (PR-reviewable); Postgres is the serving layer (an importer loads the approved JSON); Supabase Storage holds the images. This killed an earlier duplication where spots were hand-synced in two places. Adding a published city needs no app release — the app and the nudge function both read the same spots table.

05

New-engineer runbook engineering

Get it running (web is fastest)

# from the repo root
cd vantage
cp .env.example .env        # then fill in Supabase URL + anon key
npm install
npm run web                 # opens http://localhost:8081 — the whole app runs in a browser
npm test                    # the 119-test suite (jest-expo)
npx tsc --noEmit            # typecheck

The web target is how the app has been verified throughout — it exercises the real brain and UI. Native builds go through EAS (eas build --profile preview → an Android APK); iOS needs an Apple Developer account.

Where to start reading

  • Behaviour → lib/nudge.ts then lib/light.ts, lib/shootBrief.ts. The pure brain is the product.
  • Screens → App.tsx (state + layout) then the component it renders for the tab you care about.
  • Data → lib/cityPack.ts (the read) + supabase/schema.sql (the shape).
  • The "why" → the matching ADR in docs/engineering/ before you change a subsystem.

Conventions

  • Docs travel with every commit. Update BACKLOG.md / README.md / the relevant ADR when you change behaviour — it's part of "done" here, not an afterthought.
  • Decisions get an ADR. Non-trivial forks are written up in docs/engineering/*.html with the options and the call made.
  • Tests on stable, regression-prone logic — not everything. The pure lib/ functions are the tested core; rigor scales as the product validates.
  • Copy follows VOICE.md and the honesty rules. Never invent facts the app doesn't know.
Gotchas that will bite — read before your first real change

EAS builds from git, not your disk. A gitignored .env never reaches the cloud build — Supabase creds must be set as EAS env vars (eas env:create, preview env). This cost a rebuild once.

SunCalc altitude is in degrees here, not radians. There's a regression guard in light.test.ts; if a dependency bump flips it, midday stops reading as "flat" and the golden peak collapses.

Clock-skew → bundled fallback (ticket B6). On some cold loads the anonymous session token is stamped with a future-set dev clock and Supabase rejects it ("JWT issued at future"); the app degrades to the 5 bundled Atlanta spots. Self-healing, an environment artifact, not a bug — but if you ever see 5 Atlanta spots instead of 16, this is why.

Weather is a city-proxy. One forecast is fetched for spots[0] and used for the whole city — so a neighbouring grid cell's drizzle can read slightly differently from a specific spot's. Intentional simplification.

06

Product / Marketing / UX lane non-eng

You don't need the code to be effective here — you need the thesis, the voice, and the principles. Start with these.

The thesis & the strategic wedge

The positioning is sharper than "a photography app," and it's easy to state wrong: don't compete on the light — own the life. Gear-matching and a "good day" score are not open space — Fotocast already ships both (~$30/yr), so leading with them puts us head-to-head and undifferentiated. The uncontested white space (per COMPETITIVE_LANDSCAPE.html) is two things: the activity / event / street-energy dimension (no rival answers "where are the people and moments?"), and reactivating the dormant camera (everyone else serves people who've already decided to shoot). Read NORTH_STAR.html for the vision + its four product principles (inspire don't nag · personal to the bag · we reach out · lower the barrier), and PRODUCT_BRIEF.html — an honest interrogation of our own assumptions, including a live one that touches the code: golden hour may be a landscape bias, so we shouldn't down-rank flat/overcast light for street.

Voice — the brand's spine

docs/design/VOICE.md is required reading for anyone writing a word users see. The register is a knowledgeable friend who shoots: specific, grounded, never hype, never generic ("there'll be people there" is a failing sentence). The honesty philosophy (§02) is a marketing pillar as much as an engineering one — we don't fake photos, hours, or distances, and gear is always framed as what you can do.

UX principles

docs/UX_REVIEW.html drove a full polish pass (epic E7): a calm gear manager (not a wizard), confidence shown as flourish for strong nights only, honest empty states, demoted secondary CTAs so one gold action leads. The recurring UX value: curate, don't dump — the home screen is an inspiration surface, not a directory.

How the roadmap is framed

docs/BACKLOG.md is organised as epics (E0–E8). Stories are detailed just-in-time for the epic being built, not all upfront, because the product is pre-validation and requirements shift. That's deliberate — don't read the sparseness of a future epic as a gap.

07

Glossary

TermPlain meaning
Golden / blue / flat / nightThe four light phases by sun altitude. Golden = warm low sun; blue = twilight; flat = harsh high midday; night = dark. Bar colour + quality on the light chart come from this.
windowTypeA spot's best light window — golden, blue, or flat (usable across daylight). Drives when the spot is "live" tonight.
OpportunityThe unified shape a spot and an event both normalise into, so one scorer ranks both.
Eclipse ruleWhen an event and a spot share a location, the higher score headlines and the other becomes context (Dogwood Festival eclipses Piedmont Park in April, then reverts).
Photo-value gateEvery opportunity is judged on "is there a real photo here?" — magnitude/attendance amplifies but never qualifies.
The shoot briefThe E8 output under the hero: gear-readiness + shot-type guidance + rain warning — turns a "quiet night" into a plan.
genresForKit / gear-fitMapping a camera + lenses to the genres they shoot well (focal length + aperture, crop-factor aware).
Curate → Vet → Draft → Image → ServeThe five content-pipeline stages, with a human gate at Vet before any spend.
City packA city's set of published spots the app loads from Postgres (with a bundled fallback).
pg_cronThe Postgres scheduler that fires the nightly nudge Edge Function (~6pm Atlanta).
RLS / anon authRow-level security + anonymous sign-in — users get a device identity without an account; rows are scoped to it.
Expo / EASExpo = the React-Native framework/runtime; EAS = its cloud build service (produces the Android APK).

Your first week — guided paths

Ordered routes into the deeper docs, by role. Read this guide first; then follow your lane.

Engineering

  1. Run it: npm run web + npm test, and click through Today / Plan / Bag.
  2. Read the brain: lib/nudge.ts → lib/light.ts → lib/shootBrief.ts, with their tests alongside.
  3. Read TECH_DECISIONS + PUSH_ARCHITECTURE to see how the app, DB, and nightly push fit together.
  4. Trace one nudge end-to-end: App.tsx → cityPack.ts → supabase/schema.sql → functions/nudge/index.ts.
  5. Skim CONTENT_PIPELINE + GEAR_MATCHING + SHOOT_BRIEF for the subsystems you'll touch.
  6. Then read BACKLOG.md — now the shorthand makes sense.

Product / Marketing

  1. This guide → NORTH_STAR → PRODUCT_BRIEF → COMPETITIVE_LANDSCAPE.
  2. VOICE.md — internalise the register before writing anything public.
  3. Skim EVENTS_ARCHITECTURE + EVENT_DATA_SOURCES — events are the relevancy engine and the next frontier.
  4. BACKLOG.md epic headers for the roadmap shape (not every story).

UX / Design

  1. This guide → UX_REVIEW.html (the findings + the bar we hold).
  2. vantage/theme.ts + docs/design/ (VOICE, ILLUSTRATION_STYLE, the handoff) for the visual system.
  3. Run the app on web and walk every screen with the "curate, don't dump" + honesty lenses.
  4. Read SHOOT_BRIEF + GEAR_MATCHING — where product logic surfaces as copy and UI.
The one thing to remember

This app earns trust by being honest — about the light, the weather, your gear, and what's worth shooting. Every role protects that. When a change would make the app fake, hype, or over-claim, that's the bug.
